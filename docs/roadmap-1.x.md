# 1.x 改期记账

**这不是路线图承诺。** 这份文件只回答一个问题：哪些东西没有进 1.0，为什么，
以及在什么条件下应该重新考虑——不代表任何一条一定会在某个具体的 1.x 版本
交付，也不是排期表。

判定"算改期"而不是"算搁置"的最低标准：每条必须写清楚条目本身、为什么不进
1.0、什么条件下重开、决策来源。缺"重开条件"的条目不写进这里，因为那种情况
不是改期，是没人真的做过取舍决定。

追踪表（[docs/requirements-traceability.md](./requirements-traceability.md)）
里对应的行统一标注为 `**改期 1.x（决策 X）**`，可以直接 grep 数出总数；本文件
是那些标注的详细展开，不是另一份独立清单——两边应该始终指向同一组条目。

更早的版本里实际交付**，不再是候选，从上表排除，而不是遗漏：

  intent-filter），追踪表已记 Done。
- **FR-UPD-09 社区 Bundle 导入**：v0.9.0 #17 已实现（手动导入、静态检查、
  持久标记未受信任、禁止进 Stable 通道），追踪表已记 Done。

的部分留给 #13 收口时视情况处理，这里只保证 `roadmap-1.x.md` 与追踪表两边
准确，不把已经交付的东西继续当作"未来的候选"。
