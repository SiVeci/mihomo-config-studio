# ADR-015：发布渠道仅 GitHub Releases；许可证 MIT

- 状态：Accepted
- 日期：2026-08-13
- 来源：PRD §19-1、§19-3（开发前置决策第 1、3 项）

## 背景

PRD §19 把「Android 发布方式」与「项目开源许可证」列为不阻塞架构、但须在 M0
结束前冻结的前置决策，并给出默认建议：「首版通过 GitHub Releases 发布 Web
构建产物和 Android APK」。仓库根目录已有 `LICENSE` 文件（MIT），但没有记录
选择理由——决策本身存在，只是缺一条正式记录，本 ADR 补齐。这两项取值已于
2026-08-10 定为按 PRD 默认建议执行（执行计划「已确认的决策」Q3），本 ADR
不重新讨论选型，只记录背景、代价与后续动作。

## 决策一：发布渠道仅 GitHub Releases，不进应用商店

Web 构建产物与 Android APK 均只通过 GitHub Releases 分发；1.0 及可预见的
后续版本**不提交 Google Play / F-Droid 等应用商店**。

### 代价

- **无商店签名与自动更新通道**：用户需手工下载新版 APK 并允许「未知来源安装」，
  没有商店层面的静默升级；后续若做应用内更新提示，需要自建版本检查逻辑。
- **APK 分发必须自行提供校验方式**：没有商店的完整性保证，Release 附带的 APK
  必须给出可独立核验的校验信息（例如 SHA-256 摘要），否则用户无法确认下载
  内容未被篡改。这属于发布流程要求，不在 v0.1.0 范围内实现，留待正式发布
  Android 版本（v0.6.0 起）时补上。
- **无商店侧的恶意软件扫描与信任标记**：完全依赖 GitHub 账号与仓库的可信度，
  以及用户自行判断。
- **触达范围受限**：不经应用商店搜索发现，只能通过项目文档/仓库主页触达用户，
  与「社区工具，非商业推广产品」的定位一致（见决策二）。

### 后续动作

若日后决定进入应用商店，需要重新评估：应用商店的权限审查（尤其是本项目明确
拒绝的 VPN 相关权限，见 [ADR-014](./ADR-014-android-minimum-supported-version.md)
与 `docs/upstream-divergences.md`）、隐私声明（商店通常要求结构化的隐私政策
页面，当前只有仓库内文档）、以及商店签名密钥与现有 GitHub Release 产物签名的
关系。这次评估目前没有排期，不是本版本的待办事项。

## 决策二：MIT 许可证

沿用仓库现有 `LICENSE` 文件（MIT，Copyright (c) 2026 SiVeci），本 ADR 补记
理由，不改动许可证文本本身。

### 理由

- 与「社区工具、无官方隶属」的项目定位一致（README「这是什么，不是什么」一节
  已明确本项目不代表或从属于 Mihomo 官方）：MIT 是社区工具里最常见、用户与
  下游最不需要额外理解成本的许可证。
- **不对下游二次分发设限**：不强制衍生作品同样开源（不同于 GPL 系列），也不要求
  在其他项目中使用本项目代码时公开修改（不同于部分 Copyleft 许可证）。这与
  PRD 反复强调的「不做服务端、不代理用户流量、只做本地配置编辑」的克制定位
  相配——项目本身不寻求通过许可证条款控制下游使用方式。
- 与依赖的开源生态一致：`yaml`、`zod` 等核心依赖均为宽松许可证，MIT 不会
  引入许可证兼容性问题。

## 结果

- PRD §19 第 1、3 项：已落文，无待办。
- 发布 Android APK 时需要的校验信息（如 SHA-256 摘要）留给 v0.6.0 正式实现
  Android 产品壳、开始走真实发布流程时处理；v0.1.0 的 `apps/android` 是一次性
  技术验证 spike，不产出正式 Release。
- 不需要新增 `docs/upstream-divergences.md` 条目：这不是 PRD 与上游行为的冲突，
  是 PRD 明确列为待冻结的前置决策，按其自身默认建议定案。
