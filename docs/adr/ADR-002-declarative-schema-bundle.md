# ADR-002：采用声明式 Schema Bundle 热更新

- 状态：Accepted
- 日期：2026-08-10
- 来源：PRD §8.9、§9.4、§17 ADR-002

## 背景

Mihomo 字段演进速度快于应用发布节奏（PRD §18 风险表首条）。把全部字段硬编码进页面会让应用长期落后。

## 决策

把"配置知识"抽成版本化、签名的 **Schema Bundle**，与应用二进制分离发布。Bundle **只能包含数据**：

- `module.manifest.json`、`config.schema.json`（JSON Schema 2020-12）
- `ui.schema.json`（布局、控件、帮助文本、平台/版本标记）
- `validation.rules.json`（受限声明式规则 DSL）
- `migrations/*.json`、`examples/*.yaml`、`i18n/*.json`

**明确禁止**：JavaScript、Wasm、原生代码、任意表达式求值、任意正则回溯风险、文件系统访问
（FR-UPD-07、NFR-SEC-05）。规则 DSL 是一个封闭的操作码集合，由应用代码解释执行，
Bundle 不能引入新的操作码。

## 两级扩展边界

| 级别    | 内容                                                                                               | 发布方式                       |
| ------- | -------------------------------------------------------------------------------------------------- | ------------------------------ |
| Level 1 | 新字段、枚举、默认值、条件显示、文档链接、版本标记、可用现有控件表达的新协议、声明式校验/模板/迁移 | 签名 Schema Bundle，无需新 APK |
| Level 2 | 新控件类型、复杂规则图、新 YAML 语义、新原生能力、DSL 无法安全表达的算法                           | 应用构建 + 正式发布            |

## 结果

- 缩短 Mihomo 更新后的适配周期，同时避免 Android 端动态代码与供应链风险。
- 必须长期维护受限 DSL，并为其保留 100% 的测试覆盖。
- 需要签名密钥托管与双人发布审核流程（PRD §19 待冻结事项 5）。
