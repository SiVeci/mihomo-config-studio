# 用户指南

这份指南覆盖三条核心旅程（[PRD §6.2](../mihomo-config-studio-prd.md)）：模板创建、
导入已有配置、适配新版本。每一步引用的按钮/提示文案都是应用里的真实文案，不是
概括或转述——如果你在界面上没看到某段引用的文字，说明应用已经变化，请以界面
为准并提一个 issue。

这份指南不覆盖字段级细节：每个配置模块的字段说明由表单本身给出（每个字段旁的
「查看官方文档」链接指向 Mihomo 官方 wiki 的对应条目），这里不重复。

## 旅程 A：从模板起步（已知缺口）

PRD §6.2 描述的旅程 A 是"从五个内置模板中选一个开始"。**如实说明现状**：应用
目前没有应用内的模板选择器。`basic-proxy`/`provider-auto-select`/`home-router`/
`rule-set-routing`/`android-target` 五个内置模板本身已经完整实现，并且逐一通过了
针对真实 Mihomo 内核的配置测试——但这些模板还没有接入 Web/Android 界面的任何
入口，选模板这一步目前做不到。

如果你想参考某个模板的配置结构作为起点：

1. 在仓库的 `packages/templates/templates/<模板 id>/config.yaml` 中查看该模板
   的完整内容（五个 id：`basic-proxy`、`provider-auto-select`、`home-router`、
   `rule-set-routing`、`android-target`）。
2. 复制内容，按下面「旅程 B：导入已有配置」的步骤，通过「导入配置」→
   「粘贴 YAML 文本」把它当作一份已有配置导入，开始一个新项目。
3. 后续步骤（表单编辑、问题中心、导出）与旅程 B 完全相同。

这不等价于 PRD 设想的应用内模板旅程，也达不到版本发布目标里"新用户 10 分钟内
通过模板完成首次有效配置"的体验——这一条已如实记为未达成，应用内模板选择器
推迟到后续版本（决策记录见 [v1.0.0 版本计划 #6](./releases/plans/v1.0.0.md)）。

## 旅程 B：导入已有配置

1. 打开一个项目后，顶部的「导入配置」面板提供两种方式：把 `.yaml`/`.yml`
   文件拖拽到面板上（提示文字「或将 .yaml / .yml 文件拖拽到此处」），或点击
   「选择文件」用系统文件选择器；也可以直接在「粘贴 YAML 文本」文本框里粘贴
   内容，再点「导入」。
2. 应用通过真实的 YAML 解析（在后台 Worker 中进行，不阻塞界面）报告结果：
   成功显示「导入成功」；如果内容有语法错误，显示「导入失败：内容包含语法
   错误」，「原文编辑器」会定位到出错的具体行列，不会静默丢弃你的内容。
   项目自身的「目标兼容档案」是项目的一个可编辑字段（默认是应用当前锚定的
   兼容档案），需要你确认或手动调整——应用不会替你猜测导入内容对应哪个
   Mihomo 版本。
3. 你的配置里凡是本应用暂未建模的字段（比如某个模块还没图形化的冷门选项），
   会原样保留，不会因为编辑或导出而丢失，并在表单里归入「未识别字段」分组，
   附带「跳到 YAML 行」和「搜索官方文档」两个入口。
4. 已建模的字段可以在表单里编辑（「显示模式」可以在「基础」/「高级」之间
   切换）；任何字段都可以直接在「原文编辑器」里手改 YAML 原文，两边保持
   同步。规则列表有独立的「路由规则」视图，支持新建、编辑、拖拽/键盘重新
   排序、批量操作；「关系图」视图能看到代理、代理组、规则之间的引用关系，
   悬空引用或环路会被标出来。
5. 导出前，「差异」面板显示相对导入版本或最近保存版本的改动；「问题」面板
   汇总当前的错误/警告/提示（按模块筛选）。点「导出」可以导出
   `config.yaml`（原始配置）或 `.mcsproj`（含项目元数据的工程文件）；如果
   配置里含有疑似订阅地址、密码类字段、UUID 或证书私钥，导出前会先提示
   「可能包含敏感数据」，由你自己确认。存在阻断性问题时只能导出「无效
   草稿」，正常导出需要先把问题修完。

## 旅程 C：适配新版本

1. 打开「Bundle 管理」页面（项目侧栏的入口），「检查更新」区域点击
   「检查并安装」会去检查当前通道（Stable 或 Beta）是否有新的 Schema
   Bundle；已是最新版本会提示「已是最新版本」，有更新则会展示新版本号和
   兼容范围。
2. 确认后点击安装，成功会提示「安装成功，已切换到新版本」。**这一步只切换
   应用当前使用的 Bundle，不会动你已有的任何项目**（[ADR-004](./adr/ADR-004-project-locks-compatibility-profile.md)）：
   每个项目在创建时就"锁定"了当时的 Bundle 版本，新 Bundle 安装后，已有
   项目重新打开时仍然用它自己锁定的那个版本渲染表单，不会被新版本的字段
   变化影响，也不会自动帮你迁移。
3. 如果你确实想让某个项目跟上新版本，需要主动进入该项目，点击「升级
   项目」。升级前会先展示迁移预览：新增了哪些字段、废弃了哪些字段、默认值
   变化、以及每一步具体的迁移操作（重命名字段、移动字段、收窄枚举取值
   范围等）。如果某些操作可能丢失数据（比如移除字段、收窄枚举），会先给出
   「本次升级包含 N 项可能丢失数据的变更」的警告，需要你勾选「我已了解可能
   丢失数据，仍要继续」才能确认升级。
4. 升级会先创建一份安全快照再动手；如果快照创建失败或升级中途失败，应用
   会保证不做任何改动（原文不动）。如果你安装了一个新 Bundle 之后又反悔，
   「Bundle 管理」页面的「回滚」区域可以点「回滚到上一版本」退回上一个已装
   版本——这只影响应用当前使用的 Bundle，同样不会去改任何项目本身的锁定
   版本。
5. 如果你在别处手动导入了一个未经本应用信任锚点验证的社区 Bundle，界面会
   明确标它为「签名来源未验证」，且它进不了 Stable 通道；应用本身的隐私
   与依赖边界（本地优先、不上传配置）见「关于」页面的隐私摘要。

## 这份指南没有承诺什么

- 不承诺自动抓取订阅内容——「订阅地址」字段只是原样保存以供导出，应用
  从不主动请求它（`form.subscriptionUrl.notice` 的原话）。
- 不承诺任意配置在真实 Mihomo 内核上一定能跑通——本应用做的是 Schema 校验
  和内置模板/示例的内核测试，不等于对你手写的每一种字段组合都做过验证。
- 不承诺 Android 端已经过真机的全面验证——当前验证口径是模拟器
  （见 [ADR-014](./adr/ADR-014-android-minimum-supported-version.md)）。
