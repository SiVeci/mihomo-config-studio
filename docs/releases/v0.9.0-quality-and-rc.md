## 本版本要回答的问题

**PRD §13.5 的五条发布阻断项，能不能由 CI 而不是人来回答？**

功能在 v0.6.0 已经齐了。本版本不加功能，只把"我们相信它是对的"换成"CI 每次都验证它
是对的"，并补齐推迟至此的 P1 条目。

## 范围

### In scope

- 内核测试矩阵全量化
- E2E 三条线（Web / Android / 更新）
- 安全加固：CSP、日志脱敏
- 性能预算与无障碍走查
- 推迟到本版本的 P1 需求

### Out of scope

- 任何新的 P0 功能
- PRD §8.3 的 P1/P2 协议与复杂嵌套编辑器 —— 1.x

## 需求展开

### 1. 内核测试矩阵（PRD §13.3）

- CI 下载受支持的 Mihomo 核心版本并校验官方 checksum。
- 对**所有模板、模块示例和迁移结果**运行内核配置测试。
- 矩阵至少覆盖：Stable `{v1.19.29}`（ADR-012）+ Beta `{latest}`。
- **Stable Bundle 只允许发布已通过测试矩阵的版本**；Alpha/开发中字段只能进 Beta
  Bundle，并显示未稳定标记。

### 2. 端到端测试（PRD §13.4）

| 线      | 场景                                                               |
| ------- | ------------------------------------------------------------------ |
| Web     | 创建、导入、修改引用、规则排序、差异、导出、离线恢复               |
| Android | 打开文件、编辑、后台恢复、另存为、分享、**权限拒绝**、**存储不足** |
| 更新    | 安装、签名失败、应用版本不足、回滚、项目锁定                       |

### 3. 安全加固（PRD §11.3）

| 需求       | 要求                                               | 本版本落点                                               |
| ---------- | -------------------------------------------------- | -------------------------------------------------------- |
| NFR-SEC-07 | Web 部署启用严格 CSP，不加载不必要的第三方脚本     | 这正是 ADR-008 选择解释型校验器而非 Ajv 的原因，此处兑现 |
| NFR-SEC-03 | 日志和崩溃信息必须脱敏，不包含 YAML 内容和完整 URL | 建立日志脱敏工具（当前缺失），并加 CI 检查               |
| NFR-SEC-01 | 默认不把配置、订阅 URL、密钥发送到服务器           | 复核 v0.5.0 白名单化后的 `no-network-egress` 仍然有效    |
| NFR-SEC-02 | 敏感字段默认遮罩，复制和显示需要明确操作           | 全量走查，含新增模块                                     |
| NFR-SEC-08 | 项目包导出、剪贴板复制和 Android 分享前提示        | 三个入口全覆盖                                           |

### 4. 性能预算（PRD §11.1）

把 NFR-PERF-01 至 05 的指标从"记录"升级为"CI 阻断"：

| 指标        | 阈值                                            |
| ----------- | ----------------------------------------------- |
| NFR-PERF-01 | 中端 Android 首次可交互 < 2.5 秒                |
| NFR-PERF-02 | 1 MB YAML 导入、解析和首轮校验 < 2 秒           |
| NFR-PERF-03 | 常规字段编辑反馈 < 100 ms；完整校验 300 ms 防抖 |
| NFR-PERF-04 | 1,000 实体 / 10,000 规则，长列表虚拟化          |
| NFR-PERF-05 | 解析、全量校验、差异计算在 Worker 中            |

### 5. 无障碍走查（PRD §11.6）

- 错误不得只用颜色表达。
- 所有字段、按钮和拖拽操作需要键盘替代操作。
- 目标满足 WCAG 2.2 AA 的适用要求。
- 落实 ADR-011 第 2 节的三处对比度修正，并确认 CI 对比度断言覆盖全部令牌组合。

### 6. 推迟至此的 P1 需求

| 需求         | 内容                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| FR-UPD-08    | 监控上游文档与完整示例变化，自动创建待审核的更新 PR（`tools/upstream-watch`，以 v1.19.29 为 diff 基线） |
| FR-VAL-06    | 提供可由用户关闭的特定警告规则                                                                          |
| FR-YAML-08   | 格式偏好：缩进、引号、行宽、数组风格和键排序可配置                                                      |
| FR-PROJ-07   | 项目标签与搜索                                                                                          |
| FR-SCHEMA-07 | 社区贡献者可运行 Schema 开发预览和验证工具                                                              |
| FR-RULE-06   | 静态规则解释器（**必须标注不等价于内核运行时**）                                                        |
| FR-UPD-09    | 手动导入社区 Schema Bundle，显示未受信任警告（可选）                                                    |

### 7. 发布阻断项 CI 化（PRD §13.5）

五条阻断项逐条变成可执行检查：

| 阻断项                                    | CI 表达                                       |
| ----------------------------------------- | --------------------------------------------- |
| 任何内置模板未通过目标内核测试            | 内核测试矩阵                                  |
| 导入/导出会丢失未知字段                   | golden round-trip 测试                        |
| Schema Bundle 可以执行代码或绕过签名      | `schema-cli` 静态检查 + 三类否定用例          |
| 敏感配置进入日志或网络请求                | 日志脱敏检查 + `no-network-egress` 白名单守卫 |
| Android 无法可靠保存和重新打开导出的 YAML | Android E2E 线                                |

## 风险

| 风险                             | 影响                                   | 缓解                                                       |
| -------------------------------- | -------------------------------------- | ---------------------------------------------------------- |
| 性能指标改为阻断后 CI 频繁假失败 | 团队开始忽略 CI                        | 阈值留出余量，用多次采样中位数而非单次                     |
| Android E2E 在 CI 上不稳定       | 阻断项形同虚设                         | 关键路径用真机或稳定模拟器镜像；不稳定用例先隔离再修，不删 |
| P1 条目挤占加固时间              | 安全与性能被压缩                       | 加固优先；P1 未完成可改期 1.x，加固不可改期                |
| CSP 收紧后暴露隐藏的动态代码依赖 | 上线前才发现某个依赖需要 `unsafe-eval` | ADR-008 已从源头避免；本版本尽早开启 CSP 而非最后一周      |
