## 本版本要回答的问题

**引用关系能不能在真实规模上既看得懂、又改得动？**

PRD §3 把配置的核心难点定义为依赖关系：节点/集合 → 代理组 → 规则/子规则。前三个版本
建了引擎与表单，本版本才第一次让用户直接操作这条链路。同时这是唯一需要面对
NFR-PERF-04（1,000 实体 / 10,000 规则）的版本。

完成后 P0 配置模块全部就位，PRD §16.2 Beta 的"完整 P0 模块"条件达成。

## 范围

### In scope

配置模块（PRD §8.3 P0 后半）：`proxy-groups`（Select / URL-Test / Fallback /
Load-Balance）、`rule-providers`、`rules`、`sub-rules`

能力：规则编辑器、关系图、批量操作、删除影响分析、校验流水线阶段 4 与 5

### Out of scope

- 逻辑规则的复杂嵌套编辑器（PRD §8.3 列为 P1/P2）—— 1.x
- 子规则的可视化嵌套逻辑（P1）—— 1.x
- FR-RULE-06 静态规则解释器（P1）—— v0.9.0 或 1.x
- Bundle 更新 —— v0.5.0

## 需求展开

### 1. 规则编辑器（PRD §8.6）

| 需求       | PRD 要求                                           | 实现要点                                       |
| ---------- | -------------------------------------------------- | ---------------------------------------------- |
| FR-RULE-01 | 结构化创建常用规则类型                             | 域名、IP、端口、进程、GEO、RULE-SET、MATCH     |
| FR-RULE-02 | 拖拽排序，并**持续显示规则序号**                   | 引擎侧 `moveSeqItem()` 已实现且测试不丢项      |
| FR-RULE-03 | 支持批量选择、移动、复制、删除和目标策略替换       | 必须进入 v0.2.0 建立的统一历史栈（FR-PROJ-04） |
| FR-RULE-04 | 检查 MATCH 位置、明显遮蔽、缺失策略和缺失 RULE-SET | 校验流水线阶段 5                               |
| FR-RULE-05 | 高级规则可保留为原始字符串                         | 与未知字段同一保真策略                         |

**硬约束**：产品不得把静态分析结果描述为与 Mihomo 内核运行时完全等价（PRD §8.6 末句、
NG-07）。FR-RULE-04 的所有提示文案都要经过这条审查。

拖拽必须有键盘替代操作（PRD §11.6），且序号在拖拽过程中持续可见——这是 §7.3 对
Android 的明确要求，桌面端同样适用。

### 3. 校验（PRD §8.7 流水线阶段 4 与 5）

| 需求      | PRD 要求                                               |
| --------- | ------------------------------------------------------ |
| FR-VAL-03 | 对重复名称、缺失引用、循环、端口冲突和条件缺项进行检查 |

### 4. 模板补齐（PRD §8.8）

补齐余下三个内置模板：Android 生成目标配置、家庭路由器配置、规则集合分流配置。
**全部五个模板必须进入内核测试矩阵**——这是 §13.5 的发布阻断项。

### 5. 非功能

| 需求        | 要求                                                          | 本版本落点                     |
| ----------- | ------------------------------------------------------------- | ------------------------------ |
| NFR-PERF-04 | 支持至少 1,000 个可引用实体和 10,000 条规则；长列表必须虚拟化 | **本版本的硬指标**，需基准测试 |

## 退出条件

- [ ] 四个 P0 模块的字段集合与 v1.19.29 核对完毕，`mrs`/`behavior` 约束已确认
- [ ] 1,000 实体 + 10,000 规则场景下：列表虚拟化生效，编辑反馈 < 100 ms，有基准记录
- [ ] 拖拽排序有等价的键盘操作路径，序号全程可见
- [ ] 批量操作可整体撤销（单次 undo 回退整批，而非逐条）
- [ ] 删除被引用对象时无法直接删除，必须走替换或级联预览
- [ ] 循环引用被阻断并能展示环路路径
- [ ] 五个内置模板全部通过 v1.19.29 内核配置测试
- [ ] FR-RULE-04 的提示文案通过"不等价于内核运行时"审查
- [ ] `pnpm run check` 与 `format:check` 全绿，覆盖率不低于 85%

## 测试要求

- 单元：规则顺序分析（MATCH 位置、遮蔽检测）、引用完整性、端口冲突
- Round-trip：规则重排后未知字段与注释仍不丢失
- 性能：10,000 条规则的排序、批量替换、全量校验各有基准用例

## 风险

| 风险                           | 影响                   | 缓解                                                                        |
| ------------------------------ | ---------------------- | --------------------------------------------------------------------------- |
| 10,000 条规则下拖拽排序卡顿    | NFR-PERF-04 不达标     | 虚拟列表 + 只对变更区间做增量校验；必要时排序期间挂起全量校验               |
| 遮蔽检测产生大量误报           | 用户对问题中心失去信任 | 只报"明显遮蔽"（PRD 原文用词），宁可漏报不可误报；配合 FR-VAL-06 可关闭规则 |
| 关系图在大规模下不可读         | FR-REL-04 形同虚设     | 默认聚合视图 + FR-REL-06 的"仅看异常关系"筛选                               |
| 批量操作与统一历史栈的交互复杂 | 撤销行为不符合直觉     | v0.2.0 已把历史栈建在 `config-model` 层；本版本只新增操作类型               |
