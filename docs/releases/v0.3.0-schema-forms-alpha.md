## 本版本要回答的问题

**Schema Bundle 能不能真的承担字段知识，使新增一个普通字段不需要改应用代码？**

`form-plan.test.ts` 与 `form-renderer` 已经在合成样例上证明了这一点。本版本把它放到
真实的 Mihomo 字段集上验证——这是 ADR-002 整个热更新架构成立与否的实证。

Alpha 是第一个可公开试用的版本（PRD §16.1：Web 单机版）。

## 范围

### In scope

配置模块（PRD §8.3 P0 前半）：`general`、`dns`、`sniffer`、`inbound`、
`proxies`（HTTP / SOCKS / SS / VMess / VLESS / Trojan / Hysteria2 / TUIC / WireGuard）、
`proxy-providers`

新增包：`packages/schema-builtin`、`packages/schema-registry`（转正）、
`packages/templates`（雏形）、`tools/core-test-runner`（最小链路）

### Out of scope

- `proxy-groups`、`rule-providers`、`rules`、`sub-rules` —— v0.4.0
- 关系图可视化 —— v0.4.0
- Bundle 下载与通道 —— v0.5.0
- PRD §8.3 的 P1/P2 协议（AnyTLS、Mieru、MASQUE、TrustTunnel、OpenVPN 等）—— 1.x

> §8.3 明确要求：任何尚未图形化的协议或字段**必须能通过原始 YAML 编辑并被无损保存**，
> 不能因为不在 P0 列表中而丢失。这条在本版本由未知字段树 + golden 测试保证。

## 先决项

以下三项未完成则本版本不能开工：

- [ ] **`inferControl` 补齐 `oneOf` / `anyOf` 分支。** 当前实现没有联合类型分支，
      判别式联合会落到 `unknown` 控件。九种 P0 出站协议天然是判别式联合
      （按 `type` 判别），不修则 `proxies` 模块做不出来。
- [ ] **扩展 `SchemaModule` 类型。** 当前只有 `{ manifest, schema, ui }`，
      PRD §9.3 要求模块还包含 `validation.rules.json`、`examples/*.yaml`、
      `i18n/*.json`、`migrations/*.json`。本版本至少补前三项。
- [ ] **冻结 P0 出站协议字段集合。** 对照 Mihomo v1.19.29 的 `docs/config.yaml`
      逐字段核对（ADR-012 派生任务，`upstream-divergences.md` 待核对项 2）。

## 需求展开

### 1. Schema 驱动表单（PRD §8.4）

| 需求         | PRD 要求                                                                 | 当前状态 | 本版本目标                                           |
| ------------ | ------------------------------------------------------------------------ | -------- | ---------------------------------------------------- |
| FR-SCHEMA-01 | 字段表单由 Schema 和 UI Schema 动态生成                                  | Done     | 保持                                                 |
| FR-SCHEMA-02 | 支持字符串、数字、布尔、枚举、列表、映射、**联合类型**、密钥和可重复对象 | Partial  | 补联合类型控件，见先决项                             |
| FR-SCHEMA-03 | `visibleWhen`、`requiredWhen`、默认值、范围、正则、**互斥和依赖字段**    | Partial  | 补 `validation.rules` 受限 DSL（跨字段/跨对象）      |
| FR-SCHEMA-04 | 每个字段可关联官方文档、示例、平台、引入版本、废弃版本和安全等级         | Partial  | 补齐测试断言，字段元数据全量填充                     |
| FR-SCHEMA-05 | 模块可通过 Registry 注册，不依赖中央页面修改                             | Partial  | `schema-registry` 转正：模块发现、依赖解析、版本选择 |
| FR-SCHEMA-06 | 新字段在现有控件能力范围内时，可仅发布 Bundle 完成支持                   | Done     | 在真实模块上复验                                     |

跨字段规则 DSL 沿用 `condition.ts` 的受限算子集合，**不引入正则算子**
（NFR-SEC-05：攻击者提供的模式是拒绝服务向量）。

### 2. 基础模式与高级模式（PRD §7.4）

- 基础模式只展示常用、推荐且跨平台安全的字段。
- 高级模式展示全部已知字段、版本信息和原始片段。
- **切换模式不得删除或重置隐藏字段**（已有 `form-plan.test.ts`「hides advanced fields
  in basic mode without dropping them」覆盖，本版本在真实模块上复验）。
- 实验性、已废弃或平台专用字段必须带醒目标识，且不能只用颜色表达（NFR-A11Y）。

### 3. 未知字段（PRD §8.3 高级配置、§12）

- 未知字段树：保留字段，放入高级/未知区并提供官方文档搜索入口。
- FR-VAL-05：Schema 未覆盖的字段标记为 Unknown，**不判为 Error**。

### 4. 校验（PRD §8.7 流水线阶段 3 与 6）

| 需求      | PRD 要求                                                     | 本版本范围                         |
| --------- | ------------------------------------------------------------ | ---------------------------------- |
| FR-VAL-01 | 每个问题包含级别、模块、路径、行列、原因和修复建议           | 模型已在 v0.2.0 统一，本版本填内容 |
| FR-VAL-02 | 点击问题可跳转到**表单字段**或 YAML 行                       | 补齐跳转到表单字段                 |
| FR-VAL-04 | 对开放 LAN、空 Controller Secret、跳过证书校验等给出安全警告 | 流水线阶段 6                       |
| FR-VAL-05 | Schema 版本不覆盖字段时标记为 Unknown                        | 已 Done，接入问题中心              |

阶段 4（名称唯一性、引用完整性、环路）与阶段 5（规则顺序）留到 v0.4.0。

### 5. 模板与内核测试（PRD §8.8、§13.3）

本版本只做 1–2 个模板（建议「基础代理配置」与「仅代理集合 + 自动选择」），配套建立
`tools/core-test-runner` 的最小链路：下载 v1.19.29 二进制 → 校验 checksum → 跑配置测试。

提前建这条链路的原因：PRD §13.5 把「任何内置模板未通过目标 Mihomo 内核测试」列为
**发布阻断项**。第一个模板落地时就要能验证，不能等到 M6。

模板要求：声明适用的 Mihomo 版本范围和平台；变量使用明确占位符，**不包含真实密钥或
订阅**。

### 6. 订阅地址管理（PRD §8.11 P0 部分）

- 允许在 `proxy-providers` 中填写、修改、隐藏显示和复制订阅 URL。
- 支持导入本地 Provider 文件进行结构预览。
- Web 端**不承诺**直接抓取任意订阅；跨域失败时不绕过浏览器安全策略（ADR-005）。

### 7. 非功能

- **NFR-SEC-02**：敏感字段默认遮罩，显示与复制需明确操作。已在表单层 Done，本版本在
  真实的 `password` / `uuid` / `private-key` 字段上复验。
- **NFR-SEC-03**：校验消息不得包含配置值（已有测试，扩展到新模块）。

## 退出条件

- [ ] FR-SCHEMA-01 至 06 全部为 Done，每条指向具体测试文件
- [ ] 六个 P0 模块的字段集合与 v1.19.29 的 `docs/config.yaml` 核对完毕，差异已记入
      `upstream-divergences.md`
- [ ] **Golden 五步测试通过**（PRD §13.2）：导入官方完整样例 → 不改直接导出，语义树与
      未知字段一致 → 改单一字段，差异只涉及预期路径 → 再次导入导出，结果幂等 →
      注释、锚点、特殊字符串、IPv6、正则、多行密钥各有专项样例
- [ ] 每个 P0 模块都有合法、非法、边界和未知字段测试样例（NFR-MAINT）
- [ ] 内置模板通过 v1.19.29 内核配置测试
- [ ] 基础/高级模式切换不丢字段，有自动化断言
- [ ] Alpha 构建产物可离线运行
- [ ] `pnpm run check` 与 `format:check` 全绿，覆盖率不低于 85%

## 测试要求

对应 PRD §13.1 与 §13.2。重点是 golden/round-trip：**未知字段语义保留率必须是 100%**
（PRD §14.1 的 MVP 质量指标），这条由自动化测试强制，不靠人工。

## 风险

| 风险                                         | 影响                            | 缓解                                                              |
| -------------------------------------------- | ------------------------------- | ----------------------------------------------------------------- |
| 判别式联合的控件设计不足以表达九种协议的差异 | `proxies` 模块做不出来，M2 失败 | 列为先决项提前解决；必要时为"协议选择器"单独设计一个控件类型      |
| 官方文档与内核实际行为不一致                 | Schema 描述错误                 | 以内核行为为准，差异记入 `upstream-divergences.md`（既有规则）    |
| 受限 DSL 表达不了某些跨字段约束              | 只能升级应用代码（Level 2）     | ADR-002 已接受此代价；记录哪些约束被迫上升，作为 DSL 演进输入     |
| 六个模块的字段量超出 3 周                    | 排期滑坡                        | 按 §8.3 的 P0 列严格切割，P1/P2 字段一律走未知字段树而非补 Schema |
