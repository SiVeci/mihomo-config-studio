## 本版本要回答的问题

**同一份代码在 Android 上是不是真的能只靠系统能力完成文件工作？**

M0-5 已经在 spike 层面验证过，本版本是产品化：把 v0.1.0 的一次性壳换成正式集成，
并让 Web 端具备离线能力。

完成后 PRD §16.2 Beta 的四项条件全部达成：完整 P0 模块、关系图/历史/项目包、
签名 Bundle 更新与回滚、Android APK。

## 范围

### In scope

- `apps/android` 正式化：Capacitor 集成、系统文件能力、生命周期恢复
- PWA 离线缓存与安装
- PRD §7.3 的 Android 编辑器布局
- Beta 发布：Web 构建产物 + Android APK 一起发

### Out of scope

- 应用商店上架（PRD §19 已定为 GitHub Releases）
- FR-AND-07 接收其他应用分享（P1）—— 成本低时可顺带做，否则 1.x
- PRD §8.11 P1 的 Android 原生订阅抓取 —— 1.x

## 先决项

- [ ] v0.1.0 M0-5 的真机验证结论有效，Android 最低支持版本已冻结

## 需求展开

### 1. Android 能力（PRD §8.10）

| 需求      | PRD 要求                                       | 优先级 |
| --------- | ---------------------------------------------- | ------ |
| FR-AND-01 | 使用 Android 系统文件选择器打开 YAML 和项目包  | P0     |
| FR-AND-02 | 保存到用户选择的位置，**不要求广泛存储权限**   | P0     |
| FR-AND-03 | 通过系统分享面板分享 YAML 或项目包             | P0     |
| FR-AND-04 | 应用私有目录保存项目、Schema Bundle 和历史快照 | P0     |
| FR-AND-05 | 无网络时可完成所有核心编辑、校验和导出操作     | P0     |
| FR-AND-06 | 不申请 VPNService 权限，不启动后台网络服务     | P0     |
| FR-AND-07 | 支持接收其他应用分享过来的 YAML 文本或文件     | P1     |

FR-AND-06 对应 NG-01 与 NG-02，且是 PRD §13.5 的发布阻断项之一——必须有自动化检查
断言清单中不含 VPN 相关权限，不能只靠人工确认。

### 2. Android 编辑器布局（PRD §7.3）

- 顶部显示项目名、兼容档案和保存状态。
- 底部导航：配置、关系、YAML、问题。
- 长列表采用虚拟滚动；**拖拽规则时提供明确的顺序编号**。
- 支持系统文件选择器、保存位置选择器和分享面板。

### 3. PWA 与离线（PRD §11.4）

- Web 支持当前主流 Chromium、Firefox 的最近两个主要版本。
- **在不支持部分文件 API 的浏览器中回退到上传/下载模式**——不是报错，是降级。
- 离线缓存：断网后仍可完成核心编辑、校验和导出。

### 4. 生命周期与可靠性

| 需求        | 要求                                             | 本版本落点                           |
| ----------- | ------------------------------------------------ | ------------------------------------ |
| NFR-REL-02  | 应用异常退出后最多丢失最近 5 秒的编辑            | 在 Android 后台被杀场景下复验        |
| NFR-REL-05  | 存储空间不足时停止新快照、保留当前项目并提示导出 | Android 私有目录容量受限，本版本必测 |
| NFR-PERF-01 | 中端 Android 设备上首次可交互时间 < 2.5 秒       | 对照 v0.1.0 记录的基线               |
| NFR-SEC-08  | Android 分享前提示可能包含敏感信息               | 分享面板前置确认                     |

PRD §12 的失败处理要求：Android 分享失败时保留应用内副本，提供另存为和重试。

### 5. 更新链路在 WebView 上的复验

v0.5.0 的 Bundle 安装、验签与回滚必须在目标最低版本的 Android System WebView 上
重新跑通。ADR-010 记录的 Ed25519 可用性风险在此最终确认；若不可用，切换到备用实现。

## 测试要求

对应 PRD §13.4 的 Android 线：打开文件、编辑、后台恢复、另存为、分享、**权限拒绝**和
**存储不足**。后两项是容易漏测的失败路径，必须覆盖。

## 风险

| 风险                                  | 影响                     | 缓解                                                           |
| ------------------------------------- | ------------------------ | -------------------------------------------------------------- |
| 厂商 ROM 的 SAF 行为差异              | 部分设备上另存或分享失败 | M0-5 已在两个 Android 版本验证；Beta 期间收集真实设备反馈      |
| WebView 版本碎片化导致 Ed25519 不可用 | 更新链路在部分设备上断裂 | ADR-010 的纯 JS 备用实现                                       |
| 大配置在中端设备上编辑卡顿            | NFR-PERF-01/03/04 不达标 | Worker、虚拟列表、增量校验已在前序版本落地；本版本只做实测调优 |
| PWA 缓存导致用户拿到旧版本            | 更新不生效，问题难以复现 | 明确的缓存版本策略与强制刷新入口                               |
