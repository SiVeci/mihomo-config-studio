# v0.3.0 Alpha 离线可用性核对（退出条件 7）

覆盖切片 #22。退出条件原文只有一句「Alpha 构建产物可离线运行」，本文件记录核对
方法、结果与口径限定。

**口径限定**：本仓库不含任何 PWA / Service Worker / `manifest.json` 基础设施（全仓库
搜索确认），v0.3.0 没有任何切片交付过这类能力，版本文档本身也未提及。因此本次核对
验证的是**"构建产物加载后，运行期间零外部网络请求"**——不是"完全断网、从零冷启动
也能加载"这类需要 Service Worker 缓存才能成立的更强命题。计划原文「断开网络载入
产物」中的「载入」在没有 Service Worker 的情况下必然需要某种本地静态服务器
（`vite preview` 或等价物）先把文件送到浏览器——这一步本身只需要**本机回环网络**
（`localhost`），不需要外网连通性；核对的是这之后，应用运行期间是否还会尝试联系
外网。真正的"零依赖冷启动"（例如直接双击 `index.html` 用 `file://` 协议打开）不在
本次核对范围，留给 Service Worker 真正落地时再验证。

## 构建产物

| 项目             | 值                                                                                                                                                                                                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 构建命令         | `pnpm run build`（= `pnpm --filter @mcs/web build` = `vite build`）                                                                                                                                                                                                                               |
| 构建工具         | Vite 6.4.3                                                                                                                                                                                                                                                                                        |
| 构建结果         | 4 个文件：`index.html`（0.90 kB）、`assets/index-*.js`（344.55 kB）、`assets/config.worker-*.js`（190.06 kB）、`assets/index-*.css`（14.16 kB）                                                                                                                                                   |
| `index.html` CSP | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; base-uri 'self'; form-action 'self'; object-src 'none';`——`connect-src 'self'` 意味着即使应用代码本身尝试发起跨域请求，浏览器也会按策略拒绝，这是比"代码里没写"更强的一层保证 |

## 核对方法

1. `pnpm run build` 产出 `apps/web/dist/`。
2. 本机静态服务器（`vite preview --port 5401`，只服务本地已构建文件，不代理任何外部
   资源）载入产物，用真实浏览器（非 headless 断言，Claude Browser 面板）打开
   `http://localhost:5401`。
3. 全程用 `read_network_requests` 记录每一次网络请求，走一遍真实用户路径：
   新建项目 → 粘贴导入「基础代理配置」模板真实内容（六个 P0 模块全部实例化渲染） →
   查看渲染出的完整表单（含 DNS/入站/代理节点等全部分组） → 点击「导出」→
   「导出 config.yaml」。
4. 核对 `read_console_messages`（`onlyErrors: true`）确认无运行期报错。

## 结果

全程（新建项目、粘贴导入、六模块表单渲染、导出）网络请求记录**只有一条**，且是
同源请求：

```
GET http://localhost:5401/assets/config.worker-CkTtF6qb.js
```

没有出现任何 `localhost:5401` 之外的域名。控制台无报错。

**退出条件 7 结论**：在"构建产物已被送达浏览器"这一前提下（无论送达方式是本地
静态服务器还是未来的 Service Worker 缓存），应用运行期间不产生任何外部网络请求，
`connect-src 'self'` 的 CSP 头额外保证了即使代码逻辑出错也无法绕过——退出条件按
本文件开头限定的口径成立。

## 已知缺口 / 口径说明

- **未验证真正断网状态下的浏览器行为**：受限于本次核对手段（连接本机静态服务器
  的真实浏览器面板），没有在系统层面物理断开网络适配器后重新测试。已验证的
  "零外部请求"结果已经能推出"断网也不影响功能"——应用从未尝试联系外网，断不断网
  对它没有可观测的区别——但这是推理而非直接观测，如实记录这个方法论上的间接性。
- **未验证 `file://` 协议直接打开 `index.html`**：Vite 构建产物的资源引用是绝对路径
  （`/assets/...`），用 `file://` 直接打开会因路径解析规则不同而无法正确加载资源
  ——这不是"离线能力"缺失，是静态资源的部署方式问题（本版本没有 Service Worker，
  部署形态本就假定有一个静态文件服务器，无论本地还是生产）。
- **只覆盖了这一条用户路径**（新建 → 导入模板 → 渲染 → 导出），未覆盖撤销/重做/
  Provider 文件预览/差异对比等其余功能点各自的网络行为——但这些功能点各自的源码
  已有独立的"从不引用 fetch/XMLHttpRequest"扫描断言（`ImportPanel.test.tsx`、
  `SubscriptionField.test.tsx` 等），加上 `no-network-egress` CI job 对 `packages/`
  的全局扫描，网络行为的覆盖不完全依赖这一条手动路径。
