## 6. 阻断级崩溃：0

**目标**：0。**实测**：E2E 与 CI 两条线本轮零阻断级失败；**本版本没有外部
Beta 反馈输入这一半证据**（决策 I1，如实写明，不用"没人报告崩溃"冒充
"没有崩溃"）。

本片当场重跑：

```bash
pnpm run e2e
```

17 个场景，16 个通过，唯一失败是
[`e2e/long-task.spec.ts`](https://github.com/SiVeci/mihomo-config-studio/actions/runs/33991203956/job/101373640791)
的 NFR-PERF-05（`TagsControl` 对超大 `rules:` 数组的通用表单兜底路径长
任务）——这是**已经在 v1.0.0 #2/#9 记录在案、明确改期 1.x 的性能预算
未达标**，不是功能性崩溃或阻断级缺陷，详见
[docs/roadmap-1.x.md](../roadmap-1.x.md)。同一次真实 CI run 的
`typecheck / lint / test`（2249 例单测）与全部 `core-config-test`/
CSP/日志脱敏/网络出口检查均通过，没有发现新的阻断级问题。

**如实记录这条指标的真实局限**：PRD §14.1 原文的取证方式是"Beta 反馈与
E2E"，本仓库从未发布过面向公众的 Beta（决策 I1），所以这一项只有 E2E+CI
这一半证据，没有真实用户在生产环境使用后的反馈数据——"崩溃"这个词严格
意义上只覆盖了自动化测试能触达的路径，不是对全部真实使用场景的保证。
