## 工程约束（每片实现时都适用）

- Node ≥ 20.11 / pnpm 10。验收 = `pnpm run check` **和** `pnpm run format:check`。
  后者在 CI 是独立步骤，最容易漏。
- 覆盖率阈值（行 / 函数 / 语句 85、分支 80）在 `vitest.config.ts` 强制，**不得放宽**。
  #9 起 `apps/web/src/**` 一并纳入 coverage `include`，阈值不变（见 #9）。
- `packages/**` 禁止 `node:fs`（ESLint `no-restricted-imports`）与任何网络调用
  （CI `no-network-egress` job 用 grep 拦 `fetch|XMLHttpRequest|WebSocket|sendBeacon`）。
  需要平台能力的一律定义端口接口 + 由调用方注入。**注意：该 grep 作用于 `packages/**`，
  `apps/web` 不在其覆盖范围内——本版本 `apps/web` 也不得出现任何上传路径，靠 review 保证。**
- 工作区内部包直接导出 TypeScript 源码（ADR-007）：`package.json` 的 `exports` 指向
  `./src/index.ts`，不产出构建产物。`apps/web` 是消费方，由 Vite 打包。
- 新增包必须同时登记：`packages/<name>/package.json`、`tsconfig.json`、
  根 `tsconfig.build.json` 的 `references`，否则 `pnpm run typecheck` 不覆盖它。
- 用户可见文本一律 i18n key，不写字面量（ADR-016）。中英资源文件的 key 集合必须相等，
  由 #9 的断言测试强制。
- 错误与日志消息不得包含配置值（NFR-SEC-03）。`ValidationIssue` 只携带 i18n key +
  受限参数（路径、字段名、Schema 常量），**不携带用户输入的值**。
- `packages/test-fixtures/fixtures/**` 是字节敏感的 golden 文件：**只新增，不修改，
  不格式化**（已在 `.prettierignore` 与 `.gitattributes` 排除）。
- 新增架构决策写新 ADR（本版本预计占用 **ADR-017、018、019**），不改已 Accepted 的。
- PRD 与上游实际行为冲突时以上游为准，记入 `docs/upstream-divergences.md`，
  不得静默改需求。
- 分支名 `feat/v0.2.0-<切片名>`，从 **main** 切出（#0 之后 main 才有内容），
  提交信息用中文。

### #1 `validator` 骨架：统一 `ValidationIssue`

**目标**：把 `YamlIssue` 与 `SchemaIssue` 收敛为单一 `ValidationIssue`，补齐 `module`、
`range`、`fix`。

**覆盖**：FR-VAL-01；NFR-SEC-03（消息不含配置值）。

**依赖**：#0。**必须是第一个代码切片**——版本文档「风险」表明确指出这项触及两个已有包的
公开 API，趁 v0.2.0 尚无外部使用者时改，越晚成本越高。

**涉及文件**

- 新建：`packages/validator/package.json`、`tsconfig.json`、`src/index.ts`、
  `src/issue.ts`、`src/issue.test.ts`
- 修改：`packages/yaml-engine/src/issues.ts`（`message` → i18n key 口径）
- 修改：`packages/schema-core/src/validate.ts`（`SchemaIssue` 对齐字段命名）
- 修改：根 `tsconfig.build.json`（加 `packages/validator` reference）

**实现要点**

- `ValidationIssue` 字段：`severity`、`code`（稳定机器码）、`module`（产出方标识：
  Schema 模块 id，或 `'yaml'` / `'reference'` / `'security'` 等内核阶段）、
  `messageKey` + 受限 `messageParams`、`path?`、`range?`、`fix?`、`blocking`。
- **`range` 的补齐位置是适配器，不是 `schema-core`。** `schema-core` 校验的是 JS 值，
  拿不到行列；让它依赖 `MihomoYamlDocument` 会倒置依赖方向。改为：`schema-core` 继续
  只产出 `path`，`@mcs/validator` 在适配时调用 `document.locate(path)` 补 `range`。
  这既满足版本文档「为 `SchemaIssue` 补上行列 `range`」，又不污染 `schema-core`。
- `fix` 是**声明式补丁描述**，不含任何可执行内容（ADR-002 / FR-UPD-07 的同一条底线）：
  `{ kind: 'set-scalar' | 'remove' | 'rename' | 'append', path, value? }`。`value` 只允许
  取自 Schema 的 `default` / `enum` / `const`，**不得回显用户当前值**（NFR-SEC-03）。
- `messageParams` 的类型要收窄到不可能塞进配置值：只接受 `ConfigPath`、字段名字符串、
  Schema 常量。这条要有否定用例。

### #4 `storage` 端口、内存与 IndexedDB 适配

**目标**：定义存储端口，给出 Web（IndexedDB）与内存两个实现，并定义 Android 适配层接口。

**覆盖**：NFR-REL-01；FR-PROJ-02 的持久化底座；兑现 `schema-registry` 的 `BundleStore` TODO。

**依赖**：#0。

**涉及文件**

- 新建：`packages/storage/package.json`、`tsconfig.json`、`src/index.ts`、
  `src/adapter.ts`、`src/memory.ts`、`src/indexeddb.ts`、`src/indexeddb.test.ts`、
  `src/memory.test.ts`
- 修改：根 `tsconfig.build.json`

**实现要点**

- 端口：`StorageAdapter { get / put / delete / list(prefix) / estimateQuota? }`，
  值为 `Uint8Array`（不是字符串——`.mcsproj` 是二进制）。异步全 Promise。
- **Android 适配层只定义接口，不实现**（版本文档明确：Android 打包属 v0.6.0，但接口
  在本版本定义）。以 `AndroidFileAdapter extends StorageAdapter` 的形式声明所需的
  SAF / 私有目录语义差异，附 v0.6.0 的 TODO 引用，不写 Capacitor 调用
  （`packages/**` 已被 ESLint 禁止 import `@capacitor/*`）。

### #5 自动保存、快照与空间裁剪策略

**目标**：编辑后 5 秒内落盘，崩溃可恢复；快照至少保留 50 个，空间不足时按策略降级。

**覆盖**：FR-PROJ-02、FR-PROJ-05；NFR-REL-02、NFR-REL-05。

**依赖**：#3（历史项即快照来源）、#4（落盘）。

**涉及文件**

- 新建：`packages/storage/src/autosave.ts`、`src/autosave.test.ts`
- 新建：`packages/storage/src/snapshots.ts`、`src/snapshots.test.ts`

**实现要点**

- 自动保存是**注入时钟的纯调度器**，不自己 `setTimeout`：`AutoSaver { touch(now), flush() }`，
  由调用方喂时间。这样 5 秒边界可以用假时钟精确断言，不需要真实等待。
- **核心断言（NFR-REL-02）**：t=0 编辑、t=4.9s 模拟崩溃 → 重建 store 后读到的是上一次
  已落盘内容；t=5.1s 模拟崩溃 → 读到最新内容。「最多丢失 5 秒」是这条断言的字面含义。
- 浏览器侧的 `beforeunload` / `visibilitychange` 强制 flush 属 `apps/web`（#11 接线），
  本片只导出 `flush()`。
- 裁剪策略（FR-PROJ-05 + NFR-REL-05）分三级，逐级降级并各有用例：
  1. 快照数 > 50 → FIFO 淘汰最旧；

  3. 仍然写不进 → 停止快照、只保当前文档，并产出一个可供 UI 提示的降级信号
     （信号是 i18n key + 结构化数据，不含配置值）。
- 「空间不足」用注入的失败型 adapter 模拟，不依赖真实浏览器配额。

### #16 1 MB 语料性能基准

**目标**：1 MB YAML 的导入 + 解析 + 首轮校验 < 2 秒，有脚本与记录数字。

**覆盖**：NFR-PERF-02。

**依赖**：#10。

**涉及文件**

- 新建：`packages/test-fixtures/src/generate-large.ts`（生成器，非 golden 文件）
- 新建：`packages/validator/src/bench.test.ts` 或 `bench/import.bench.ts`
- 新建：`docs/releases/plans/v0.2.0-perf-baseline.md`（记录数字与方法）
- 修改：`.github/workflows/ci.yml`（基准 step，**只记录不阻断**）

**实现要点**

- **1 MB 语料用确定性生成器，不提交 1 MB 文件**。理由：`fixtures/**` 是字节敏感的
  golden 目录，塞一份 1 MB 生成物进去既污染 golden 语义又让每次 clone 变重。
  生成器用固定种子，同输入必得同输出，基准可复现。
- 生成的语料要**像真配置**：大量 rules、proxies、proxy-groups、注释与锚点，
  而不是一行重复 10 万次——否则测的是解析器的最好情况。
- 基准同时记录三段耗时：解析、首轮校验、总计。退出条件只卡总计 < 2s，但分段数字
  是后续优化的唯一抓手。
- **CI 只记录不阻断**（版本文档明确：阻断阈值留到 v0.9.0）。CI runner 性能波动大，
  这个阶段设阻断线只会制造假警报。
- 数字写进 `v0.2.0-perf-baseline.md`：机器型号、Node 版本、采样次数、中位数，
  格式参照 `v0.1.0-android-evidence.md`。

**验收命令**

```bash
pnpm run check && pnpm run format:check && pnpm vitest bench --run
```

**完成后更新的文档行**：追踪表 NFR-PERF-02 → Done（指向基准文件与记录文档）。

## 已确认的决策

四项在规划阶段提出并已定案，实现时直接执行，不再重开讨论。

**D1 —— 对比度断言表的范围（→ #7、#8）**
补一层 `text-*` 文字承载色，断言表覆盖 `canvas` 与 `surface-card` 两个底色。
背景：ADR-011 §2 只算了 `canvas`，复算发现 `warning` #d4a017 作文字 = 2.25、
`success` #5db872 = 2.33、`accent-teal` = 2.25、`accent-amber` = 2.00；
在 `surface-card` #efe9de 上 `muted` = 4.48、`primary-active` = 4.19、`error` = 4.01，
全部不到 4.5——若不处理，退出条件「CI 对比度断言通过」必然 fail。
落地方式：新写 **ADR-017**，**不修改已 Accepted 的 ADR-011**。

**D2 —— `.mcsproj` 的 ZIP 实现（→ #6）**
零依赖手写 ZIP 读写，压缩走平台内置 `CompressionStream('deflate-raw')`。
与 ADR-008（自建 JSON Schema 校验器、不引第三方）同一条供应链姿态，且产物字节
确定性可控，往返一致性好断言。

**D3 —— 浏览器级证据的验证工具链（→ #5、#10、#16）**
本版本用 vitest + 假件（假 Worker、`fake-indexeddb`、假时钟），真 E2E 留 v0.9.0
——该版本文档本就以「内核测试矩阵、E2E、安全与性能」为主题。
**代价已知并接受**：「主线程无长任务」是结构性证明（主线程模块图不直接依赖引擎），
不是真实 timing 测量。这条要在 #17 的追踪表证据列里如实写明口径，不得含糊标 Done。

**D4 —— 分支基线（→ #0）**
先把 `chore/scaffold-baseline`（`d95dc9b`）合入 `main`，之后每个 `feat/v0.2.0-*`
都从 main 切出、合回 main。合并动作由你执行。
