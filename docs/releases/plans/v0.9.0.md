## 工程约束（实现时必须遵守，逐片适用）

- Node ≥ 22.18 / pnpm 10（#1 抬高，ADR-030）。**每片验收都是 `pnpm run check` 和 `pnpm run format:check` 两条**，
  后者 CI 单独跑、最容易漏。#7 起追加第三条 `pnpm run e2e`（只在改动触及 `e2e/**` 或
  `apps/web/**` 时必跑）。
- 覆盖率阈值 85% 在 `vitest.config.ts` 强制，**不得放宽**。`e2e/**` 不进 vitest 的
  `include`，也不进 coverage 的 `include`——它是独立运行器，不参与这个数字。
- `packages/**` 禁止 `node:fs`（ESLint 强制）与任何网络调用（CI `no-network-egress` job
  强制，白名单是路径精确的）。**新建的 `packages/logging` 必须是纯函数包，零依赖、零 IO**。
- `packages/**` 禁止 `import '@capacitor/*'`（ESLint 强制）。
- 工作区内部包直接导出 TypeScript 源码（ADR-007），不新建构建步骤。`packages/logging`
  同样不例外。
- 用户可见文本一律走 `apps/web/src/i18n` 的 key，`zh-CN.json` 与 `en.json` 同步新增
  （`i18n.test.ts` 的键集合对等检查 + `TranslationKey` 类型会在 `typecheck` 阶段拦下漏项）。
- **错误与日志消息不得包含配置值（NFR-SEC-03）**。本版本这条从「约定」升级为「工具 +
  CI 强制」（#5/#6），新写的每一条错误路径都要能过 `tools/log-redaction-check`。
- `packages/test-fixtures/fixtures/**` 是字节敏感 Golden 文件，不格式化、不顺手整理。
- 新增架构决策写新 ADR，不改已 Accepted 的。
- PRD 与上游实际行为冲突时以上游为准，记入 `docs/upstream-divergences.md`，不得静默改需求。
- **本版本特有**：#1 之后每一片都会在真实 CI 上被验证。**本机绿 ≠ 验收通过**——从 #1 起，
  每片的完成判据追加一条「该片提交推送后 CI 五个（#7 起七个）job 全绿」。

  Bundle 版本间没有可用的迁移契约，如实记为「本版本无迁移产物可测」并保留结构——
  **不造一个假的迁移契约来凑数**。

    推导不符，按原计划记入 `docs/upstream-divergences.md`，不静默改期望值。

**实现要点**

- **本仓库目前有五处内联样式**（本轮实测）：`AppShell.tsx:96` 的 `<style>` 元素，
  外加 `GraphView.tsx:193`、`RuleListPage.tsx:338/363/398` 四个 `style={{height}}`
  属性。二者受不同指令管辖，必须分开处理——这正是 ADR-032 存在的理由：
  - `<style>` 元素受 `style-src-elem` 管。它当初存在的理由是「`@media` 条件读不到 CSS
    自定义属性」。解法：把断点值 `768px`（= `tokens.ts` 的 `BREAKPOINTS.mobile`）
    **字面写进一个真实 `.css` 文件**，并加一条单测断言这个字面值与令牌值相等——令牌
    改了而 CSS 没改，测试立刻红。这样 `style-src-elem` 就能收到 `'self'`。
  - 四个 `style={{height}}` 受 `style-src-attr` 管。它们是虚拟列表与画布的**逐元素
    几何值**，改成 CSS 类等于给每个可能的高度生成一个类，不可行。决策：
    `style-src-attr 'unsafe-inline'` **保留**，并在 ADR-032 里写清楚为什么这不削弱
    XSS 防护（`style` 属性无法执行脚本；真正危险的 `script-src`/`style-src-elem`
    都已收到 `'self'`）。**不假装做到了没做到的事。**
- 最终策略（以 ADR-032 与实现为准，此处是设计意图）：
  `default-src 'none'; script-src 'self'; style-src-elem 'self'; style-src-attr 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; worker-src 'self'; manifest-src 'self'; font-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; object-src 'none';`

- **`csp-check` 检查的是构建产物，不是源码**：读 `apps/web/dist/index.html`，断言
  (a) 策略字符串与期望逐字符相等，(b) 无 `unsafe-eval`，(c) 无
  `style-src-elem`/`script-src` 上的 `'unsafe-inline'`，(d) **产物里没有任何指向
  外部源的 `<script src>` / `<link href>`**（"无非必要第三方脚本"这条退出条件的机器

### #5 `packages/logging`：日志脱敏核心（NFR-SEC-03）

**目标**：建起追踪表挂了七个版本的「日志脱敏工具」，作为纯函数包，先把判定逻辑做对
并测透，再谈接线。

**覆盖**：退出条件 4（工具部分）；NFR-SEC-03 的缺口前半。

**依赖**：#1。

**涉及文件**

- 新建 `packages/logging/`（`package.json`、`tsconfig.json`、`src/index.ts`、
  `src/redact.ts`、`src/redact.test.ts`、`src/logger.ts`、`src/logger.test.ts`）
- 修改 `tsconfig.build.json`：加入新包的 project reference

**实现要点**

- **零依赖、零 IO、零 `node:*`**。这是 `packages/**`，ESLint 已强制禁 `node:fs`；
  本包连 `node:crypto` 也不用（脱敏不需要哈希，需要的是丢弃）。
- `redact(text: string): string` 的封闭规则集（**宁可过度脱敏，不可漏**，与 ADR-018
  的 `describeSensitivity` 同一取舍）：
  1. **完整 URL → 只保留 scheme + host**：`https://sub.example.com/a/b?token=x` →
     `https://sub.example.com/<redacted>`。NFR-SEC-03 原文是"不包含完整 URL"，保留
     host 便于排障，路径与 query 是真正带密钥的部分。
  2. **多行文本 → 整段丢弃**，替换为 `<redacted:N lines>`。YAML 内容几乎必然多行；
     与其逐字段识别，不如从形态上拒绝——这是"不包含 YAML 内容"最可靠的表达。
  3. **单行里出现 `key: value` 形态 → 只留 key**。
  4. **形似凭据的裸串**（UUID、Base64 ≥ 32 字符、PEM 块头）→ 整体替换。
- `createLogger({sink})` 返回 `{debug, info, warn, error}`，**每个方法都强制过
  `redact`**——没有"跳过脱敏"的逃生口。`sink` 注入（默认 `console`），单测用假 sink
  捕获输出。
- **测试语料必须是真实配置**：从 `packages/test-fixtures` 拿真实样例（含订阅 URL、
  password、uuid、PEM 私钥块），断言脱敏输出里**这些原文一个字节都不出现**。手法
  与 `mcsproj.test.ts`「never includes the matched secret value anywhere」一致。
- **同时要有反向用例**：脱敏不能把有用信息全吃掉。断言错误码、路径、字段名、模块名
  这四类仍然可读——一个只输出 `<redacted>` 的日志系统等于没有日志。
- `Error` 对象的处理：`redact` 作用于 `message` 与 `stack`（栈里可能有 data URL）。

**实现记录（2026-08-29）**

- **规则优先级与计划编号顺序不完全一致，已按实测行为记清楚**：对一条 `key: value`
  形态的行，"只留 key"（计划的规则 3）优先于"URL 只留 scheme+host"（规则 1）——
  例如 `subscription-url: https://sub.example.com/...` 直接变成
  `subscription-url: <redacted>`，不会先把 URL 处理成 `.../<redacted>` 再保留。
  规则 1 的 scheme+host 保留只在**裸 URL 出现在自由文本里**（不是 `key: value` 形态）
  时生效，例如 `failed to fetch https://sub.example.com/...`。这样两条规则不会互相
  打架，且满足反向用例"key 名称仍可读"的字面要求。
- **新增一条计划未列出的子规则：`data:` URL**。计划原文特别点名"栈里可能有 data
  URL"，但通用的完整 URL 规则要求 `://`，`data:` scheme 没有这个分隔符（`data:
text/plain;base64,...`），会被漏判。已加专门的 `DATA_URL` 正则，整体替换为
  `data:<redacted>`（不尝试保留任何部分——data URL 没有"host"可保留）。
- **`packages/logging/src/logger.ts` 需要一条窄范围 ESLint 例外**：仓库既有
  `no-console: allow: ['warn','error']` 规则会拦下 `CONSOLE_SINK` 里的
  `console.debug`/`console.info`——但这个文件的全部职责就是做那个允许全部四个
  方法的唯一封装。`eslint.config.js` 新增一条只针对这一个文件路径的例外，写明
  原因；仓库其余 `packages/**`/`apps/web/**` 的 `no-console` 口径不变。

**覆盖**：退出条件 2（更新线）；PRD §13.4 更新行；退出条件 7 的第三条阻断项（Schema

**实现记录（2026-08-30，两处与计划文字的偏离，均有具体理由）**

- **测试 Bundle 不签发到 `e2e/bundles/` 再提交产物，而是现场生成**：计划原文设想"生成脚本进仓库，产物也进仓库"，理由是 Ed25519 密钥生成不确定性下"避免 CI 上每次重新签发引入不确定性"。实际实现（`e2e/bundle-fixtures.ts`）反过来——每次 `playwright.config.ts` 求值时现场生成密钥对并签发四种 Bundle 变体（安装用/回滚第二个/错误签名/应用版本过低），从不提交私钥或签名产物字节。理由：(1) 密钥生成不确定性意味着提交的产物一旦生成就无法用同一份源码重新验证是"对的"，只能盲目信任一次性生成的字节，这与本仓库"自建的东西必须可读、可测、可控"的路线冲突；(2) `MCS_TRUST_ANCHOR_OVERRIDES_JSON` 与 `MCS_BUNDLE_UPDATE_SOURCES_JSON` 本来就要在 `vite build` 前动态确定，现场生成公钥直接写入这两个变量，比"先提交固定产物、再想办法让公钥与之匹配"更直接。**为避免 `webServer.reuseExistingServer`（本地默认 `true`）复用一个用旧密钥构建的服务导致信任锚点不匹配**，生成结果缓存进 `e2e/.generated/`（已加入 `.gitignore`）并跨次本地运行复用，只在该目录不存在时（含每次全新的 CI checkout）才真正重新生成——`loadOrGenerateBundleFixtureSet` 的注释记录了这条推理。
- **`.github/workflows/ci.yml` 未追加步骤**：计划原文预期需要给 `e2e-web` job 加一步来签发测试 Bundle。由于签发已经内嵌进 `playwright.config.ts` 自身的求值过程，`pnpm run e2e`（`e2e-web` job 已有的唯一步骤）本身就端到端完成生成+签发+构建+测试，不需要任何额外命令。
- **`e2e/` 提升为真正的 pnpm 工作区包**（新建 `e2e/package.json`，`pnpm-workspace.yaml` 加入 `"e2e"`）：不在计划的"涉及文件"清单里，但属于"必要的小补充"——`packages/schema-registry/src/verify.ts` 的 `canonicalManifestJson` 原文明确要求"签名方必须导入这个确切的函数而不是重新实现，签名方与校验方之间任何字节级差异都会变成一个无法解释的假阴性签名失败"；`e2e/` 此前不是工作区成员，无法以包名方式导入任何 `@mcs/*` 包，唯一不越过包边界手写相对路径导入内部文件的正规做法就是让它成为真正的工作区依赖方。密钥生成本身仍是本地小函数（与 `apps/web/src/testing/signed-bundle.ts`/`packages/schema-registry/src/testing/keys.ts` 同一先例：这部分没有"必须与别处字节一致"的约束）。
- **真实浏览器验证抓到一处纯测试可靠性问题（非产品缺陷）**：Service Worker 一旦通过 `clients.claim()` 接管页面，`sw.ts` 的 `fetch` 监听器会拦截页面发出的每一个请求并在 **Service Worker 自己的执行上下文里**重新发起 `fetch`——这个重新发起的请求 `page.route()` 看不见（`page.route()` 只看页面自身发出的请求），会真的打到 `vite preview`，对一个从未真实存在于磁盘上的路径（`/e2e-bundle/manifest.json`）返回真实 404，表现为 `UPDATER_FETCH_FAILED`。回滚场景的第二次安装、项目锁定场景经过项目创建+导入后才安装，都给了 SW 足够时间完成激活+接管，因此稳定复现；第一次安装因为发生得早，SW 通常还没接管，所以不受影响——这与 #7 发现的首装刷新竞态是同一个"SW 接管时机不确定"主题的另一处表现，但这次的正确修法在测试层：`update.spec.ts` 的 `beforeEach` 用 `page.addInitScript` 让 `navigator.serviceWorker.register` 直接拒绝，因为这份测试本来就与离线/SW 行为无关（那是 `web.spec.ts` 自己的 ADR-029 场景），不是产品代码需要修的东西。
