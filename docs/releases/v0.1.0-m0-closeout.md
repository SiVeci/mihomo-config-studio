## 本版本要回答的问题

M0 的目的不是交付功能，是**在投入后续 14 周之前证明三件事不会推翻架构**：引用能不能
在无损回写的前提下级联改名、Bundle 签名链能不能在客户端闭环、Android 能不能只靠系统
能力完成文件读写。

M0-1（YAML 无损 Round-trip）与 M0-2（Schema 驱动表单）已通过，本版本清掉剩余三项。

## 范围

### In scope

1. M0-3 引用模型与关系图 —— 新增 `packages/config-model`、`packages/graph`
2. M0-4 Bundle 校验、签名与回滚 —— 新增 `packages/schema-registry`、`tools/schema-cli`
3. M0-5 Android 文件能力 —— 新增 `apps/android`
4. ADR-009 引用模型；冻结 PRD §19 剩余决策

### Out of scope

- 任何图形界面。本版本所有产出都是包与命令行，不建 `apps/web`。
- 任何具体 Schema 模块内容（general / dns / proxies 等）留到 v0.3.0。
- Android 壳可以是一次性 spike，不要求达到 v0.6.0 的产品质量。

## 先决项

无。本版本是起点。

## 需求展开

### 1. M0-3 引用模型与关系图

落点：`packages/config-model`、`packages/graph`

按 PRD §10 建立核心实体：

| 实体        | 字段                                         |
| ----------- | -------------------------------------------- |
| `Entity`    | `id`、`kind`、`serializedName`、`sourcePath` |
| `Reference` | `fromId`、`toId`、`path`、`referenceType`    |

| 需求      | PRD 要求                                                  | 本版本验收要点                                                  |
| --------- | --------------------------------------------------------- | --------------------------------------------------------------- |
| FR-REL-01 | 为节点、Provider、代理组、规则集合、子规则生成内部稳定 ID | 修改 `serializedName` 后 `id` 不变；`id` 不进入导出的 YAML      |
| FR-REL-02 | 重命名时级联更新引用                                      | 改代理组名后，引用它的 `rules`、`proxy-groups.proxies` 全部更新 |
| FR-REL-03 | 删除前影响分析                                            | 能列出全部引用方，且能区分"可替换"与"必须级联删除"              |
| FR-REL-05 | 循环检测                                                  | 代理组互引、`dialer-proxy` 链路成环时被阻断并给出环路路径       |

**已知技术难点**：路由规则里的引用不是独立 YAML 节点，而是字符串的尾段
（`DOMAIN,example.com,PROXY-GROUP` 中的 `PROXY-GROUP`）。引用索引必须能定位到标量
**内部的子片段**，级联改名才不会破坏规则文本。这是 M0-3 真正要验证的风险点，不是
建两个数据结构。

**验证证据**：对 `packages/test-fixtures/fixtures/yaml/comprehensive.yaml` 建索引 →
改一个代理组名 → 回写 → 用 `diffLines()` 断言变更行集合恰好等于预期集合。

### 2. M0-4 Bundle 校验、签名与回滚

落点：`packages/schema-registry`、`tools/schema-cli`

严格按 ADR-010 实现：Ed25519 签名 + 逐文件 SHA-256，Web Crypto `SubtleCrypto` 实现。

| 需求       | PRD 要求                                                | 本版本范围                    |
| ---------- | ------------------------------------------------------- | ----------------------------- |
| FR-UPD-01  | 内置一个经过测试的默认 Bundle，可完全离线工作           | 最小骨架即可，内容留到 v0.3.0 |
| FR-UPD-03  | 更新前验证 manifest、哈希、签名、格式版本和应用最低版本 | **完整实现**，本版本的核心    |
| FR-UPD-04  | 保留最近两份可用 Bundle，并支持一键回滚                 | **完整实现**                  |
| FR-UPD-07  | Bundle 不能包含或执行 JavaScript、Wasm、原生代码        | 静态检查落到 `schema-cli`     |
| NFR-SEC-04 | 必须通过哈希与数字签名验证                              | 同 FR-UPD-03                  |

**验证证据**：三类否定用例必须**拒绝安装且回落到上一版本**，缺一不可。

1. Bundle 内某个文件被篡改（哈希不匹配）
2. 用另一把私钥重新签名（签名不匹配内置公钥）
3. `formatVersion` 或 `requiresApp` 不满足

**必须一并实测**：Web Crypto 的 Ed25519 在目标最低 Android 版本的 System WebView 上
是否可用。这是 ADR-010 记录的待验证风险；不可用则改为打包一份经审计的纯 JS 实现，
托管与审批部分不变。

### 3. M0-5 Android 文件能力

落点：`apps/android`（Capacitor 壳，允许一次性）

| 需求      | PRD 要求                                   |
| --------- | ------------------------------------------ |
| FR-AND-01 | 使用系统文件选择器打开 YAML 和项目包       |
| FR-AND-02 | 保存到用户选择的位置，不要求广泛存储权限   |
| FR-AND-03 | 通过系统分享面板分享 YAML 或项目包         |
| FR-AND-04 | 应用私有目录保存项目、Bundle 和历史快照    |
| FR-AND-06 | 不申请 VPNService 权限，不启动后台网络服务 |

**验证证据**：真机跑通「打开 → 编辑 → 另存 → 重新打开」完整链路，Android 9 与最新版
各一台。同时用 `aapt dump permissions` 或等价手段断言清单中不含 VPN 相关权限
（对应 NG-02，是 §13.5 的发布阻断项之一）。

**附带产出**：记录冷启动时间作为 NFR-PERF-01（首次可交互 < 2.5s）的基线；据此冻结
Android 最低支持版本，关闭 `upstream-divergences.md` 的第 4 项待核对。

## 风险

| 风险                                              | 影响                                         | 缓解                                                                             |
| ------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------- |
| 标量内子片段的引用定位比预期复杂                  | FR-REL-02 级联改名不可靠，动摇 §8.5 全部需求 | 这正是 M0-3 要提前暴露的风险；若不可行，改为"改名前先解析规则为结构化形式再回写" |
