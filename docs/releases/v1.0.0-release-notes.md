# Mihomo 配置工坊 v1.0.0

面向 Web 与 Android 的、本地优先、Schema 驱动的 Mihomo 配置生成与管理工具。

**这是 1.0 正式版**——从 v0.1.0 起沿着[版本执行计划](./README.md)逐版本交付，
本次收口了发布阻断项清零与正式发布，详见[需求追踪表](../requirements-traceability.md)
与 [v1.0.0 执行计划](./plans/v1.0.0.md)。已知缺口见下方"已知缺口"一节——
**本发布说明不会把任何未完成的事说成已完成**。

本项目是社区工具，与 MetaCubeX 官方**无隶属或背书关系**。Mihomo 名称和上游项目
归其相应权利人所有。

## 这是什么，不是什么

**是**：一个图形化创建、导入、理解、校验、维护和导出 Mihomo YAML 配置的工具。

**不是**：

- 不运行 Mihomo 内核
- 不是代理 / VPN 客户端，**不申请 Android `VPNService` 权限**
- 不提供账号、云同步或在线配置托管
- 不通过项目服务器代抓订阅

配置数据默认只在本地处理。订阅 URL、密码、UUID、证书和私钥不会被上传到任何服务器。

## 下载与校验

本次发布包含两个产物，均可从本 Release 的 Assets 直接下载：

- `mihomo-config-studio-web-v1.0.0.zip`：Web 构建产物，解压后可用任意静态文件
  服务器托管（需支持 Service Worker，见下方"离线与 PWA"）。
- `mihomo-config-studio-v1.0.0.apk`：已签名的 Android 安装包。

`SHA256SUMS.txt` 同样作为本 Release 的一个下载资产附带两个产物的 SHA-256
校验值——不只是写在构建日志里，下载后可自行核对：

```bash
sha256sum -c SHA256SUMS.txt
```

## Android 安装说明

本项目**不在应用商店分发**（[ADR-015](../adr/ADR-015-release-channel-and-license.md)，
仅 GitHub Releases + MIT 许可），安装 `.apk` 前需要在系统设置里为浏览器/文件管理器
临时开启"安装未知应用"权限。

**可自行复核本应用不申请 VPN 权限**：用 Android SDK 自带的 `aapt2` 对下载到的 APK
运行：

```bash
aapt2 dump permissions mihomo-config-studio-v1.0.0.apk
```

输出中不应出现 `android.permission.BIND_VPN_SERVICE`，也不应出现
`READ_EXTERNAL_STORAGE`/`WRITE_EXTERNAL_STORAGE`/`MANAGE_EXTERNAL_STORAGE`/
`ACCESS_BACKGROUND_LOCATION`——这份白名单由
[`tools/android-manifest-check`](../../tools/android-manifest-check) 在构建期对源码清单与
产物本身各断言一次，本发布工作流已经跑过，此处的自行复核是可选的、面向不信任构建产物
的用户。

**最低支持版本**：Android 10（API 29）。低于该版本，或该版本设备的 WebView 内核
过旧（缺 `String.prototype.replaceAll`/`Array.prototype.at`/`Object.hasOwn` 任一
能力）时，应用会显示明确的"浏览器版本过旧"提示而不是白屏或崩溃
（[ADR-027](../adr/ADR-027-minimum-webview-baseline.md)、
[ADR-036](../adr/ADR-036-minimum-version-two-tier.md)）——**这条是能力门触发与否
的达标口径，不等价于在真机上完整走过一遍交互流程**，见下方"已知缺口"。

## 离线与 PWA

Web 版本可安装为 PWA，断网后仍可继续编辑已打开的项目（[ADR-029](../adr/ADR-029-service-worker-cache-strategy.md)）。
不支持 File System Access API 的浏览器会自动回退到上传/下载模式，不影响核心编辑功能。

## Schema Bundle 更新：Stable 通道已开张

与 v0.9.0-rc 不同，本次发布**已经配置了真实的 Stable 更新源**：内置 Bundle
本身已用生产 Ed25519 密钥重签（不再是开发期的一次性密钥），首个 Stable Bundle
（`schema-v0.9.1`）已作为独立的 GitHub Release 真实发布并通过端到端验证（真实
HTTP 拉取 + 签名校验 + 客户端消费）。打开"Bundle 管理"页点击"检查并安装"即可
体验完整的检查更新流程。Beta 通道仍未配置远端源。

## 已知缺口

**本节逐条列出——不在发布说明的其它地方隐藏或淡化这些缺口。**

- **本版本没有外部公开 Beta 反馈输入**：本仓库从未发布过面向公众的 Beta，
  缺陷来源是内部真实 CI/内核测试矩阵/端到端测试三条线，不是真实用户反馈。
- **Android 端到端测试未接入 CI**：`connectedAndroidTest`（真实 UIAutomator）
  基础设施已就绪，但受阻于一个环境相关的 UI 时序问题，未能让全部场景稳定通过，
  目前仍只由本机模拟器人工执行，详见
  [v0.9.0-android-e2e-evidence.md](./plans/v0.9.0-android-e2e-evidence.md)。
- **PRD §13.5 第五条发布阻断项（Android 保存/重新打开可靠性）仍由人工回答**：
  与上一条同一根因，决策是不为此在无 KVM 的免费 CI runner 上引入第三方模拟器
  action，详见 [docs/release-blockers.md](../release-blockers.md)。
- **NFR-PERF-01（首次可交互 < 2.5s）的达标口径是模拟器**，没有真机基线数据。
- **API 29 设备可能只会看到能力门提示，而不是应用界面本身**：这是
  ADR-036 记录的既定分层设计（安装门槛 API 29、运行时门槛 WebView 107），
  已验证能力门本身能正确触发，但没有在真实的 API 29 设备上走完一遍完整交互。
- **应用内没有模板选择/创建入口**：`packages/templates` 的五个内置模板本身
  （数据 + 内核测试）已完整交付，但尚未接入应用界面——"新建项目"目前只能从
  空白配置开始。已推迟到后续版本，详见 [docs/roadmap-1.x.md](../roadmap-1.x.md)。
- **英文界面没有实际的切换入口**：中英文两份 i18n 资源已完整且强制同步，
  但代码库里没有任何组件调用语言切换 API，也没有基于浏览器语言的自动检测。
- 其余明确改期到 1.x 的条目（上游监控自动化、YAML 导出格式偏好等）统一记在
  [docs/roadmap-1.x.md](../roadmap-1.x.md)，不在这里逐条重复。
