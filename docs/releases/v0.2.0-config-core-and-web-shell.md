## 本版本要回答的问题

**不装任何 Schema 模块，用户能不能完成一次完整的「导入 → 原文编辑 → 看差异 → 导出」？**

如果能，那么之后每个 Schema 模块都是可独立验证的垂直切片，而不是必须凑齐一整套才能
看到东西。这条判据决定了本版本的取舍：宁可先把壳和存储做扎实，也不提前做字段表单。

## 范围

- `packages/storage`、`packages/project-format`、`packages/ui`

- Bundle 下载与更新 —— v0.5.0
- Android 打包 —— v0.6.0（但 `storage` 的 Android 适配层接口在本版本定义）

## 需求展开

### 1. 项目管理（PRD §8.1）

落点：`packages/config-model`、`packages/storage`、`packages/project-format`

| 需求       | PRD 验收要点                            | 实现要点                                                               |
| ---------- | --------------------------------------- | ---------------------------------------------------------------------- |
| FR-PROJ-01 | 可设置名称、描述和目标兼容档案          | 目标档案默认取 v1.19.29（ADR-012）                                     |
| FR-PROJ-02 | 编辑后 5 秒内落盘，刷新或重启应用可恢复 | 对应 NFR-REL-02，需自动化验证而非人工刷新                              |
| FR-PROJ-03 | 删除前二次确认；支持导出后删除          | —                                                                      |
| FR-PROJ-04 | 表单、拖拽、批量操作均进入**统一**历史  | 历史栈建在 `config-model` 层而非 UI 层，否则 v0.4.0 的批量操作无法并入 |
| FR-PROJ-05 | 至少保留最近 50 个快照或由空间策略裁剪  | 空间不足时的降级行为对应 NFR-REL-05                                    |
| FR-PROJ-06 | 支持 YAML 和便携项目包 `.mcsproj`       | 见下                                                                   |

`.mcsproj` 为 ZIP 容器（PRD §8.1），至少包含：

```text
manifest.json       项目元数据和格式版本
config.yaml         当前 Mihomo 配置
ui-state.json       折叠状态、内部实体 ID 等非 Mihomo 数据
schema-lock.json    Schema Bundle 锁定信息
```

导出前必须提示可能包含敏感数据（NFR-SEC-08）。

### 2. YAML 导入、编辑与导出（PRD §8.2）

落点：`apps/web` + 已有的 `packages/yaml-engine`

| 需求       | PRD 验收要点                                                 | 缺口                                     |
| ---------- | ------------------------------------------------------------ | ---------------------------------------- |
| FR-YAML-01 | 支持 `.yaml`、`.yml` 和纯文本粘贴                            | 引擎已就绪，缺文件/剪贴板入口            |
| FR-YAML-04 | 显示行号、语法错误、查找、格式化和跳转                       | 引擎侧 `locate()` 已提供行列定位         |

| FR-YAML-06 | 导出前显示相对导入版本或最近保存版本的差异                   | `diffLines()` 已实现，缺面板             |
| FR-YAML-07 | 正常导出 `config.yaml`；存在阻断错误时只能"导出无效草稿"     | 需要 validator 骨架提供阻断判定          |

### 4. 校验骨架（PRD §8.7）

落点：`packages/validator`

本版本只做**流水线与统一 Issue 模型**，不含具体校验规则：

- 统一 `YamlIssue`（`yaml-engine`）与 `SchemaIssue`（`schema-core`）为单一
  `ValidationIssue`，补齐 PRD §8.7 要求但目前缺失的 `module` 与 `fix` 字段，
  并为 `SchemaIssue` 补上行列 `range`。这是追踪表已记录的缺口。
- 落地 FR-VAL-02：点击问题跳转到 YAML 行（跳转到表单字段留到 v0.3.0）。

### 5. 设计系统（ADR-011）

落点：`packages/ui`

- 将 `DESIGN.md` 的 `spacing` / `rounded` / `typography` / elevation / 断点落为 CSS
  自定义属性与 TS token 导出。
- 应用 ADR-011 第 2 节的对比度修正：`primary-active` #a9583e 承载文字，`primary`
  #cc785c 只做大面积填充；caption 改用 `muted`。
- 扩展令牌：密度尺度、表单状态全集、亮/暗主题对、hover 规范。
- **CI 增加对比度断言**，令牌组合不达 AA 即 fail。
- 将 `DESIGN.md` 迁至 `docs/design-system.md`，同步修改 `.prettierignore` 中的路径条目。

## 退出条件

- [ ] 不安装任何 Schema 模块，可完成「导入 → 原文编辑 → 差异 → 导出」完整闭环
- [ ] 1 MB YAML 导入解析 + 首轮校验 < 2s，有基准测试脚本与记录数字
- [ ] 解析、校验、差异确认运行在 Worker 中，主线程无长任务
- [ ] 自动保存与崩溃恢复有自动化验证，最多丢失 5 秒编辑
- [ ] `.mcsproj` 导入导出往返一致，含敏感数据提示
- [ ] 撤销重做覆盖表单编辑与引用改名两类操作，走同一历史栈
- [ ] `ValidationIssue` 已统一，含 `module`、`range`、`fix`
- [ ] `packages/ui` token 已落地，CI 对比度断言通过
- [ ] `pnpm run check` 与 `format:check` 全绿，覆盖率不低于 85%

## 测试要求

- 单元：存储适配层、快照裁剪策略、`.mcsproj` 往返、历史栈合并与撤销边界
- Round-trip：沿用 `test-fixtures` 的 golden 用例，确认接入 UI 后仍无损
- 性能：1 MB 语料的导入基准，纳入 CI 但只记录不阻断（阻断阈值留到 v0.9.0）

## 风险

| 风险                                    | 影响                                 | 缓解                                                   |
| --------------------------------------- | ------------------------------------ | ------------------------------------------------------ |
| Worker 边界划错，AST 需跨线程传递       | 结构化克隆开销吃掉性能收益           | Worker 内持有 Document，主线程只传路径与补丁，不传 AST |
| 统一 Issue 模型触及已有两个包的公开 API | `yaml-engine`/`schema-core` 需改接口 | 趁 v0.2.0 尚无外部使用者时改，越晚成本越高             |
| `packages/ui` 令牌与扩展边界模糊        | 后续贡献者不知道哪些能改             | ADR-011 要求扩展令牌显式标注来源                       |
