# 版本执行计划

本目录把 [PRD](../../mihomo-config-studio-prd.md) 的里程碑（§15）与发布范围（§16）
展开为逐版本的执行文档。

**PRD 是需求来源，本目录是执行计划。** 两者冲突时以 PRD 为准；若因上游实际行为而必须
偏离，按规则记入 [上游差异记录](../upstream-divergences.md)，不得静默修改需求。

## 文档结构约定

每份版本文档包含固定章节：

1. **元信息** —— 对应里程碑、发布性质、预估周期、前置依赖
2. **本版本要回答的问题** —— 一句话说明这个版本存在的理由
3. **范围** —— In scope 与 **明确的 Out of scope**
4. **先决项** —— 开工前必须完成的事，未完成则本版本不能开始
5. **需求展开** —— 逐条 FR/NFR，含实现落点与验收要点
6. **退出条件** —— 可验证、可勾选，未满足不得进入下一版本
7. **测试要求** —— 对应 PRD §13
8. **风险**

## 排期口径

PRD §15 按两名主要开发者、10 周估算。本仓库目前是单人开发，按 PRD 自己给出的单人口径
**16–20 周**排期，其中 Schema、YAML 无损回写和兼容测试三项不压缩。

各版本的"预估周期"均为单人口径。

## 状态口径

与 [需求追踪表](../requirements-traceability.md) 一致：任何标记为完成的条目都必须能
指向具体测试文件。版本文档的退出条件不是宣告，是验收清单。

## 未进当前版本的条目

条件下应该重新考虑——不是路线图承诺，只是一份如实的改期记账。
